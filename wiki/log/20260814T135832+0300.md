# 2026-08-14 13:58 - Add implementation page for self-hosted favicon discovery (favicon-fetcher.mjs)

Created an implementation guide describing how to replace the Google Favicon
service in `@akashacms/plugins-external-links` with build-time, self-hosted
favicon discovery, per the user's specification.

## Analysis

- Read the Vendor Library Plugins architecture page to reuse the
  `addAssetsDir({ src, dest: '/vendor/LIBRARY-NAME' })` mounting pattern for the
  `/vendor/favicon-cache` automount.
- Read the Key-Value Store and Image Resizing concept pages; confirmed Sharp is a
  direct dependency of AkashaRender (`lib/built-in.ts:24`, used at line 317 as
  `sharp(srcfile).resize(width)`) and that built-in.ts writes resized images
  straight into `config.renderDestination`.
- Confirmed the external-links plugin's current Google `<img>` in
  `mahafuncs.mjs` (lines 160–165), its async `process()` and de-dup/suppress
  logic, the `configure()` option-defaults + fluent-setter pattern in
  `index.mjs`, and that the plugin's `package.json` `dependencies` is empty (so
  `sharp`/`cheerio` must be added).

## Changes

- Wrote `wiki/implementation/favicon-fetcher-self-hosted.md` with the standard
  implementation-page sections (Query, Architecture Pages, Architecture,
  Sources, Related Pages, Backlinks). It specifies: the per-canonical-domain
  on-disk cache layout with `meta.json` + icon bytes and negative-result
  caching; the `favicon-fetcher.mjs` module (fetch with redirects + faux
  User-Agent, cheerio-based discovery of `icon`/`apple-touch-icon`/`mask-icon`/
  manifest icons with `/favicon.ico` fallback, ranking by desired size,
  download, store); the optional lazy-Sharp resize/convert-to-PNG snippet that
  **never converts ICO** (store ICO as-is); the `index.mjs` config options
  (`faviconCacheDir` default `favicon-cache`, `faviconSize`,
  `faviconConvertToPNG`, timeout), abs-dir resolution, `mkdir`, and the
  `/vendor/favicon-cache` automount plus fluent setters; the `mahafuncs.mjs`
  change to emit a local `<img>` while preserving de-dup/suppress/classes; and
  a phased plan, testing checklist, and security/robustness notes.
