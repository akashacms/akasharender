# 2026-08-14 00:26 - Add external-URL whitelist to Link Checker guide

Extended the Link Checker implementation guide to specify a configurable
**whitelist of external URLs that are never checked** (assumed valid, never
fetched).

Rationale captured in the document: bot-blocked hosts (Cloudflare/WAF `403`,
LinkedIn `999`), auth-walled resources (`401`), rate-limited/fragile endpoints,
and politeness/speed. Whitelisted URLs are short-circuited to `OK` before any
HTTP request.

Changes made to `wiki/implementation/link-checker.md`:

- Query section now states the whitelist requirement.
- New explanatory subsection in section 3 (external links) covering why the
  whitelist is needed, string/host-prefix/`RegExp` matching, and the
  distinction between `whitelist` and `ignore` (plus a noted future
  `blacklist`), cross-referencing the external-links plugin's
  `whitelist`/`addWhitelistEntry` pattern.
- Added `whitelist: []` to the default `checkLinks` options block.
- Added a `whitelist` entry to both `config.mjs` configuration examples.
- Added the chainable `addLinkCheckWhitelist(config, entry)` setter and an
  `isWhitelisted(url, whitelist)` helper description.
- External `checkUrl` reference implementation now short-circuits whitelisted
  URLs before fetching; whole-site scan filters the whitelist at dedupe time.
- Testing strategy adds whitelist test cases (exact/host/RegExp matching; fetch
  mock never called for whitelisted URLs) and Phase 3 mentions the whitelist.
- Updated `last-updated` frontmatter timestamp.
