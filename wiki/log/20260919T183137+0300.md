# 2026-09-19 18:31 - Removed the traces (TRACES table) subsystem from AkashaRender

Completed GitHub issue akashacms/akasharender#267: fully removed the
`TRACES` SQLite table subsystem, which had been dead code since the
2026-09-03 removal of the legacy string-returning render path deleted
its only writer (`data.report()`). No caller of `data.init`,
`data.remove`, `data.removeAll`, or `data.print` was doing useful work
— the CLI created the table and immediately truncated it on every run,
and nothing ever inserted a row.

## Analysis

Repo-wide grep confirmed the only remaining call sites of `lib/data.ts`
were:

- `lib/index.ts:156` — `import { init } from './data.js'` and
  `lib/index.ts:222` — `await init()` inside `setup()`.
- `lib/cli.ts:30` — `import * as data from './data.js'` and
  `lib/cli.ts:181` / `lib/cli.ts:217` — `await data.removeAll()` in the
  `render-document` and `render` subcommands.
- `lib/render.ts:23` — `import * as data from './data.js'` with **no
  references** in the file (a leftover from the 2026-09-03 cleanup).

Test suite (`node --test ./index.mjs` and `test-rebased`) contained no
`TRACES` or `data.*` references. `test-cache` was already failing on an
unrelated `minimatch` ESM import problem before this change.
