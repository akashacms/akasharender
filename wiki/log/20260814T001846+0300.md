# 2026-08-14 00:18 - Add Link Checker implementation guide

Created a new implementation-design page describing how to add a link-validity
checker to the AkashaRender Built-in Plugin (`akashacms-builtin`).

The design covers:

- **Internal links** validated by looking up the rendering path in the
  documents/assets cache, reusing the resolution logic already present in the
  `AnchorCleanup` Munger and honoring `askPluginsLegitLocalHref`.
- **External links** validated over HTTP using the best-practice
  HEAD-then-GET pattern with Node 24's global `fetch` and
  `AbortSignal.timeout()`, including status-code classification, User-Agent,
  redirect/retry/backoff, concurrency + per-host limits, and dedupe/caching.
- **Four severity modes** (ignore / warn / error / fatal) with a defined
  reporter contract; `error` collects failures and throws from
  `onSiteRendered` at the end (failing the run), while `fatal` throws at first
  detection.
- **Configuration** from `config.mjs` matching the built-in plugin pattern
  (`config.plugin('akashacms-builtin').checkLinks = {...}`) plus chainable
  setter methods modeled on the external-links plugin.
- File placement, a whole-site `onSiteRendered` scan, a reference `checkUrl`
  implementation, a `node:test` testing strategy, and a phased plan.

The external-URL best-practice research was gathered from the maintained
`linkinator` and canonical `broken-link-checker` libraries and Node.js
`fetch`/`AbortSignal` semantics.

Also registered the new page in `wiki/implementation/README.md` and
`wiki/index.md`, and refreshed the index `last-updated` timestamp.
