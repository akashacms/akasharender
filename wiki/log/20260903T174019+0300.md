# 2026-09-03 17:40 - Phase 2 executed - legacy render functions deleted, 2-suffixes dropped

Executed Phase 2 of the legacy-render-functions removal plan.

## Changes

- lib/render.ts: deleted `renderDocument`, `render`, `renderContent`,
  `writeCSStoOutput`, `copyAssetToOutput`; renamed `renderDocument2` →
  `renderDocument`, `render2` → `render`, `Render2Options` → `RenderOptions`;
  file reduced 1095 → 695 lines
- lib/index.ts: deleted legacy `renderPath`; renamed `renderPath2` →
  `renderPath`; extracted the copy-pasted lookup-polling loop into private
  `findDocumentWithRetry`; fixed `module_exports` (now exports exactly
  `render`, `renderDocument`, `renderPath`)
- lib/cli.ts: call sites updated to `akasha.renderPath` / `akasha.render`
- lib/data.ts: removed `report()` and `data4file()`; deleted
  `lib/sql/data-add-report.sql` and `lib/sql/data-for-file.sql`
- test/index.mjs, test/rebased.mjs, test/test-relative.mjs: call sites now
  `akasha.render(config, { forceRenderAll: true })`
- Wiki pages updated to describe the single implementation: render.ts and

  answers, rendering-pipeline / template-rendering / performance-tracing /
  performance-measurement-methodology concepts, memory page retitled

## Analysis

- With `report()` removed, nothing writes to the TRACES table. The remaining
  functions (`init`, `remove`, `removeAll`, `print`) stay because the CLI
  calls `removeAll()` and akasharender-epub calls `init()`. TRACES apparatus
  is a future-removal candidate tied to issue #212.
- Version NOT bumped: bumps are dedicated release-time commits on this
  branch. Recommend 0.11.0 at next release since this is API-breaking.
