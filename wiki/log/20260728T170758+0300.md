# 2026-07-28 17:07 - Add answer page for UNIQUE constraint failed on ASSETS.vpath

Created a new answer page documenting the cause and resolution of the
`UNIQUE constraint failed: ASSETS.vpath` (and `DOCUMENTS.vpath`) errors seen when
running commands such as `npx akasharender assetdirs config.mjs`.

## Analysis

- The error is logged from `BaseCache.setup()` in `lib/cache/cache-sqlite.ts`, where
  per-file insert failures are caught and printed as
  `Error gathering info for <vpath>: ...`.
- The insert is a plain (non-upsert) `INSERT` into a table whose `vpath` column is the
  `PRIMARY KEY` (`lib/cache/sql/create-table-assets.sql`).
- The directory scan cannot be the source of duplicate vpaths: `VFStack` dedupes by
  vpath in its `#vpathMap` (`lib/cache/vfstack.ts`).
- Tables are created with `CREATE TABLE IF NOT EXISTS` and never truncated at the start
  of `setup()`.
- Root cause: when `AK_DB_URL` (read in `lib/sqdb.ts`) points at a persistent file
  instead of the default `:memory:`, rows from a prior run survive and the fresh
  inserts collide on the `vpath` primary key.
- Resolution: unset `AK_DB_URL`, set it to `:memory:`, or start from an empty database
  file.
