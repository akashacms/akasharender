# 2026-09-26 23:00 - Fix AnchorCleanup mangling fragment-carrying hrefs (vendor-prepended PDF link); tabler-icons findByPath fix

Follow-up to the 22:40 session.  The remaining example-site warning
(`internal link not found (/vendor/img/adobe-Test.pdf)`) was NOT a missing
file (correcting the earlier log's claim): the source references
`/img/adobe-Test.pdf`, which exists at `documents/img/adobe-Test.pdf` and
`out/img/adobe-Test.pdf`.  The document-viewers plugin emits
`/vendor/Viewer.js/index.html#../../../img/adobe-Test.pdf` (Viewer.js
resolves the fragment relative to itself), and `AnchorCleanup`'s
relativization let the fragment participate in path arithmetic:
`relative()`/`path.normalize` folded the `#../../../img/…` segment chain
into `../vendor/img/adobe-Test.pdf` — the mangled rendered href.

## Changes

- `lib/built-in.ts` (AnchorCleanup): split the href into path / query /
  fragment before any path arithmetic; relativize only the path and
  re-append query/fragment verbatim; a path that strips to empty
  (`#name`, `?x`) returns `"ok"` early (fixes the footnotes plugin's
  `#name` anchors throwing `resolveVpath: relativePath must be a non-empty
  string`).
- `../tabler-icons/index.mjs`: `findIcon`/`findFilledIcon` now use
  `assetsCache.find()` instead of `findByPath()` — the ASSETS cache stores
  vpaths without the leading slash and `findByPath` is exact-match, so the
  leading-slash lookup returned `[]` and rendering
  `tabler-icons.html.md` failed with `TablerIconsElement no vpath for …`.
- `test/index.mjs` + `test/documents/anchor-cleanups*.html.md` (4 template
  variants): regression fixtures/assertions for `a#fragment-preserved`
  (fragment carrying a relative path) and `a#same-page-anchor`
  (fragment-only href).

## Verification

- akasharender full test suite: 408 tests, 0 failures.
- `../akashacms-example` rendered with `--force-render-all` after syncing
  `dist/` and the tabler-icons plugin into its `node_modules`:
  **0 errors, 0 warnings**; `out/viewer-js-viewer/pdf-spec-link.html`
  contains `../vendor/Viewer.js/index.html#../../../img/adobe-Test.pdf`;
  tabler icons render (`<img id="category-img-filled"…>`, `<svg>`).
- Note: incremental renders skip up-to-date documents; `--force-render-all`
  was required to surface the footnotes/tabler-icons errors at all.
