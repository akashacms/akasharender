# 2026-08-14 13:08 - Add answer page on favicon formats and direct discovery without Google

Created a new answer page documenting how favicons work, the supported image
formats for favicons, and how to discover a site's favicons directly — in
service of the plan to change `@akashacms/plugins-external-links` so it no
longer uses the Google Favicon service (`www.google.com/s2/favicons`), which
risks having site visitors tracked by Google.

## Analysis

- Read the external-links plugin sources: `ExternalLinkMunger.showFavicons` in
  `mahafuncs.mjs` hard-codes an `<img src="https://www.google.com/s2/favicons?domain=...">`,
  so the icon is fetched by each visitor's browser from Google at page-view
  time (leaking IP/User-Agent/Referer). `index.mjs` wires the `showFavicons`
  option; the plugin does not discover favicons at all today.
- Read the plugin's `TODO.md`, which states the intent to replace the Google
  service with direct discovery, caching, local storage, and an
  `<i class='ak-favicon-ref'>` client-side rewrite, and lists candidate npm
  packages.
- Read the plugin guide pages, which document the favicon feature, the
  `akashacms-external-links-suppress-icons` opt-out, and note that a Google
  service is currently used.
- Confirmed favicon standards (MDN `rel` attribute / `icon` value): discovery
  via `<link rel="icon">` (plus `apple-touch-icon`, `mask-icon`, and Web App
  Manifest `icons`) with the `/favicon.ico` root convention as fallback;
  multiple icons are ranked by `type`/`sizes`/`media` with last-one-wins;
  supported formats are ICO (multi-size container), PNG, and SVG as the modern
  set, with GIF/JPEG/WebP/AVIF tolerated.
