# 2026-08-14 00:37 - Add optional logging of non-HTTP links to Link Checker guide

Replaced the fixed `skipSchemes` denylist in the Link Checker implementation
guide with a scheme-agnostic, allowlist-based approach, and added an optional
feature to log non-http/https links.

Rationale: there are dozens of registered URI schemes (`mailto:`, `tel:`,
`sms:`, `ftp:`, `file:`, `geo:`, `magnet:`, `xmpp:`, `bitcoin:`, `spotify:`,
...), so enumerating skippable schemes is a losing game. The robust rule is the
inverse: validate only `http:`/`https:` URLs (over the network) and local paths
(via the cache), and treat every other scheme as a non-checkable "non-HTTP
link." A new `reportOtherSchemes` option (using the same
`ignore | warn | error | fatal` enum) optionally logs those links — defaulting
to `'ignore'` (silent skip), with `'warn'` giving an inventory (scheme + href +
source) to catch typo'd schemes and stray `javascript:`/`mailto:` links.

Changes made to `wiki/implementation/link-checker.md`:

- Query section notes the http(s)-only allowlist rule and the optional logging
  of non-HTTP links.
- Section 3 rewritten: "Non-HTTP schemes — allowlist, do not denylist" plus the
  `reportOtherSchemes` optional-logging subsection; scheme detected via
  `new URL(href, base).protocol`; bare `#` treated as a same-page anchor.
- Options block: removed `skipSchemes: [...]`; added `reportOtherSchemes:
  'ignore'`.
- Config examples add a `reportOtherSchemes: 'warn'` example; added the
  chainable `setOtherSchemesMode(config, mode)` setter.
- Whole-site scan now classifies by scheme first (anchor → skip; non-HTTP →
  `reportOtherSchemes`; else internal/external), with dedupe.
- `LinkChecker` sketch adds `#reportOtherScheme(href, sourceDoc)` and notes
  scheme classification in `checkLink`.
- Testing strategy adds non-HTTP-scheme cases; Phase 2 mentions scheme
  classification and `reportOtherSchemes`.
- Updated `last-updated` frontmatter timestamp.
