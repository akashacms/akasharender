# 2026-07-07 00:16 - Added answer page on SQLite date/time storage options (issue #120)

The user asked to check the implementation of date/time values in the
in-memory SQLite database, in the context of
[issue #120](https://github.com/akashacms/akasharender/issues/120), and to
document the options for storing date/time values as a wiki answer page.
The user intends to reference the page from a comment on the issue and then
close it.

## Analysis

- Explored `lib/cache/sql/*.sql`, `lib/cache/cache-sqlite.ts`,
  `lib/cache/schema.ts`, `lib/cache/vfstack.ts`, `lib/sql/data-create-table.sql`,
  `lib/data.ts`, and `lib/render.ts` to determine how date/time values are
  written, stored, indexed, and read.
- Found two conventions: epoch milliseconds for the file-cache columns
  (`mtimeMs` REAL, `publicationTime` INTEGER generated via
  `json_extract(info, '$.publicationTime')`), and ISO-8601 text for the
  TRACES table.
- Found a stale comment in `lib/cache/schema.ts` (lines 331-339) describing
  `publicationTime` as "seconds since Jan 1 1970" when the code stores
  milliseconds.
- Compared the SQLite-supported storage formats (ISO-8601 TEXT, Julian day
  REAL, Unix epoch seconds) plus epoch milliseconds and the sqlean `time`
  extension, per the references cited in issue #120.

## Changes

- Created the answer page
