# 2026-07-31 23:05 - Add answer page on lightweight image-resize alternatives to sharp

The user asked whether a small Node.js package could replace `sharp` for the
built-in image-resize feature, to reduce the installed size of `akasharender`.
Current usage handles JPEG/PNG and SVG, and WebP output should also be
supported. This work captured the research as a new answer page and cross-linked
it.

## Analysis

- Inspected the only sharp usage in the codebase: `lib/built-in.ts` uses just
  three calls — `sharp(srcfile)`, `.resize(width)`, and `.toFile(dest)`
  (source: lib/built-in.ts:249-268).
- Confirmed via `built-in-guide/index.html.md` (lines 189-192) that format
  conversion via the `resize-to` extension (PNG→JPG) is a documented,
  required feature — so a replacement must select the output encoder by
  destination extension for at least JPEG, PNG, and WebP.
- Identified that sharp's large footprint is bundled native libvips binaries,
  so only pure-JS (Jimp) or WASM (photon-node, Squoosh codecs) libraries
  actually reduce install size.
- Noted SVG rasterization is a hard gap: plain Jimp and most WASM raster
  codecs cannot decode SVG.
- Flagged a contradiction: the `image-resizing` concept page's "No Format
  Conversion" pitfall contradicts the built-in guide.

## Recommendations

- Correct the "No Format Conversion" pitfall in
  `wiki/concepts/image-resizing.md` to reflect that PNG→JPG conversion via
  `resize-to` is supported.
- Before switching libraries, verify installed-size deltas, current WebP encode
  support/quality, and decide the SVG policy (rasterize, copy-through, or error).
