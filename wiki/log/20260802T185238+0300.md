# 2026-08-02 18:52 - Revise csv-table guide for external data files and csv-parse

Revised the `<csv-table>` implementation guide following maintainer feedback on
two points:

1. **Data-file location.** Data files may live in an assets directory, a
   documents directory, or outside the project directories entirely — and keeping
   the raw data file outside the project is often preferable so the data source is
   not copied into the deployed site. Replaced the `CodeEmbed`-style
   documents-cache-only lookup with a three-tier `resolveDataFile` helper (assets
   cache → documents cache → filesystem), modeled on the existing
   assets-then-documents fallback at `lib/built-in.ts`:239-245 and extended with a
   filesystem fallback (absolute path, or relative to a configured data root).
   Added a dedicated "File resolution" section documenting the three sources, the
   non-deployment benefit, security/traversal considerations, and open design
   decisions (where relative external paths resolve; whether to add a configurable
   data root). Updated the element code block, error handling, tests (file
   resolution across all three sources plus a check that external data is not
   emitted), phasing, gotchas, and the tag attribute table accordingly.

2. **CSV parsing.** Removed the "minimal internal parser" option; the guide now
   mandates using a mature, tested package — `csv-parse` (`csv-parse/sync`) — and
   adds a Phase 0 to add it to `package.json`. `js-yaml` remains for YAML.

Also added `lib/cache/cache-sqlite.ts` to the page Sources (for `assetsCache`/
`documentsCache` and `find`) and refreshed the page `last-updated` timestamp.
