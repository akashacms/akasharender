# 2026-08-14 00:31 - Clarify ignore mode vs whitelist in Link Checker guide

Reconciled the meaning of `ignore` in the Link Checker implementation guide so
that the two concepts are cleanly separated:

- **`ignore`** is the `ignore` **severity mode** and means "completely ignore
  link checking" for a class of links (internal and/or external). Setting a
  mode to `'ignore'` performs no cache lookup and no HTTP request and reports
  nothing; `internal: 'ignore'` + `external: 'ignore'` disables the feature.
- **`whitelist`** skips link checking for **specific domains** only, while
  external checking is otherwise on.

Changes made to `wiki/implementation/link-checker.md`:

- Removed the redundant `enabled` master-switch flag; the `ignore` mode is now
  the off switch. Updated the options block, both `config.mjs` examples (added
  an explicit "turn checking off" example), the setter methods (dropped
  `checkLinksEnabled`), and the `AnchorCleanup` / `onSiteRendered` wiring notes
  to gate on `mode !== 'ignore'` instead of `options.checkLinks.enabled`.
- Renamed the former scheme/shape `ignore: []` array to `skipSchemes` to stop
  overloading the word "ignore"; whole-site scan now references `skipSchemes`.
- Rewrote the "whitelist vs ignore" subsection to state the two different
  scopes (mode = wholesale off; whitelist = per-domain), and reframed the
  whitelist as primarily a domain list.
- Updated the four-modes section: `ignore` now documents that the class of
  checking is skipped entirely.
- Updated the testing strategy (assert no cache lookup / no fetch when a class
  is `'ignore'`; dropped `addLinkCheckIgnore` from the config-API test).
- Updated `last-updated` frontmatter timestamp.
