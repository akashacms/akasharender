# 2026-08-14 01:00 - Link Checker guide - on-demand import() model for link-check

Revised the build-vs-buy recommendation in the Link Checker implementation guide
so that `link-check` is integrated as a site-author-owned, optionally-loaded
dependency rather than a dependency of AkashaRender.

New integration model documented:

1. The site author installs `link-check` in THEIR project
   (`npm install --save-dev link-check`); it is not a dependency or
   peerDependency of AkashaRender.
2. The author selects it via config (`checkLinks.externalChecker: 'link-check'`).
3. The plugin lazy-loads it with dynamic `import('link-check')` only when
   selected, resolving from the project's node_modules, memoized after first
   use, with a clear "install link-check" error when the package is absent. The
   default (`'fetch'`) imports nothing.

This mirrors AkashaRender's existing runtime loading of the config/plugins
(`await import(configFN)`, `require(PluginObj)` in `Configuration.use`).
