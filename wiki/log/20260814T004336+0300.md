# 2026-08-14 00:43 - Add build-vs-buy evaluation of link-check to Link Checker guide

Added a build-versus-buy evaluation of the `link-check` npm package
(https://www.npmjs.com/package/link-check, https://github.com/tcort/link-check)
to the Link Checker implementation guide.

Facts gathered from the package's npm page and GitHub repo (v5.6.0): HEAD-then-
GET liveness check with redirect following; `aliveStatusCodes` (supports
RegExp); `retryOn429` with `retryCount`/`fallbackRetryDelay` honoring
`Retry-After`; `timeout`, custom `user_agent`, custom `headers`, `baseUrl`;
`anchors` (fragment) checking; `mailto:` verification via node-email-verifier;
callback API; ISC license; ~233k weekly downloads; 59 dependents; 47 GitHub
stars; 5 dependencies; published within the last month.

Assessment recorded in the guide: `link-check` covers exactly the commodity
per-URL check but provides none of the AkashaRender-specific harness (internal-
link cache resolution, HTML crawl, dedupe/concurrency/caching, whitelist,
`reportOtherSchemes`, four-mode severity/reporter). Recommendation: "buy the
per-URL check, build the harness" — define a single
`checkExternalUrl(url, opts) => Promise<{ state, status }>` boundary with two
interchangeable implementations (default zero-dependency `fetch`; optional
`link-check` adapter selectable via `checkLinks.externalChecker`).
